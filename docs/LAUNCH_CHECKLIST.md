## 2. โควตา Supabase (ดูทุกวันหลังเปิดตัว)

ช่วงผ่อนผันของ Supabase หมดเมื่อ 22 พ.ย. ตอนนี้ใช้ Fair Use แล้ว ถ้าใช้เกินโควตาของแผนฟรี เว็บจะถูกระงับทันที และทุกคำขอที่อ่านฐานข้อมูลจะได้ 402 **25 พ.ย. เว็บจริงถูกระงับไปช่วงหนึ่ง** เพราะรอบบิลก่อนใช้ egress ไป 12.53 GB จาก 5 GB ระบบปลดเองเมื่อเริ่มรอบบิลใหม่ (egress รีเซ็ตเหลือ 0.005 GB ฐานข้อมูล 71 MB จาก 500 MB) **เจ้าของเลือก 25 พ.ย.: อยู่แผนฟรีไปก่อน** ช่วงหลังใช้วันละ 150–200 MB พอราว 25–33 วัน สมาชิกที่ใช้งานจริงเพิ่มคนละราว 3 MB ต่อวัน ถ้าเพิ่มวันละ 50 คน จะเต็มในราว 2 สัปดาห์

- [ ] `เจ้าของ` **ดู egress ทุกวันหลังเปิดตัว แล้วอัปเกรด Supabase เป็น Pro ทันทีเมื่อเกิน 2.5 GB** (ครึ่งโควตา) หรือเมื่อตัวเลขขึ้นเร็วจนน่าจะเกิน 5 GB ก่อนจบรอบ ดูที่ Supabase > Organization Duke > Usage org นี้อยู่บน Vercel Marketplace จึงอัปเกรดผ่านปุ่ม Upgrade plan ซึ่งจะพาไปจ่ายที่ Vercel ไม่ต้องแก้โค้ดหรือ `DATABASE_URL` Pro ($25/เดือน) ให้ 250 GB (Claude วิเคราะห์ 16 พ.ย.: คนใช้ 1,000 คนต่อวันจะราว 90 GB ต่อเดือน) ได้ช่องเชื่อมต่อมากกว่า 29 และ Point-in-Time Recovery ด้วย
- [ ] `Claude` **ลด egress รอบใหม่** (วัดจาก `pg_stat_statements` บนเว็บจริง 24 พ.ย.) (1)–(2) ~~รายการสถานที่ อีเวนต์ ชาเลนจ์ทั้งก้อน~~ ทำแล้ว BE-481 (gzip บน R2 อ่านฐานครั้งเดียวต่อการแก้ข้อมูล) เจ้าของดู egress หลัง deploy ว่าลดลงจริง (3) postgres.js อ่าน `pg_type` ทุกการเชื่อมต่อใหม่ เพราะ `max: 1, idle_timeout: 5` ทำให้ต่อใหม่บ่อย (ระวัง pool 29) (4) หน้ารายละเอียดสถานที่อ่านเฉพาะคอลัมน์ที่ใช้ แทน `select *` (5) ~~หน้ารายละเอียดเก็บที่ CDN~~ ทำแล้ว BE-472 (สถานที่ อีเวนต์ ตี้ ชาเลนจ์) ที่เหลือ: หน้ารายการและหน้าแรกของคนที่ยังไม่ล็อกอิน วัดใน Supabase > Usage > Egress ก่อนและหลัง
- [ ] `เจ้าของ` **ดู Vercel > Observability > Data Cache** ว่ามี hit จริง เพื่อยืนยันว่า cache ข้ามเซิร์ฟเวอร์ทำงาน
- [ ] `เจ้าของ` **secrets ของงานรูปที่เที่ยวบน GitHub Actions (BE-467)** GitHub > Settings > Secrets and variables > Actions ใส่ `PLACES_DATABASE_URL` = `POSTGRES_URL` ใน `.env.local` โดยเปลี่ยน `:6543` เป็น `:5432` (ห้ามสร้างรหัสใหม่ให้ app_runtime เพราะเว็บจริงจะล่ม), `R2_ACCOUNT_ID` และ `R2_BUCKET` จาก Cloudflare R2, `R2_PUBLIC_URL` = `https://media.chillwaa.com`, `R2_ACCESS_KEY_ID` + `R2_SECRET_ACCESS_KEY` จาก token ใหม่ (R2 > Manage API Tokens, Object Read & Write เฉพาะ bucket เว็บจริง แสดงครั้งเดียว) หรือรัน `! gh auth login` แล้วให้ Claude ใส่ค่าด้วย `gh secret set` จากนั้นกด Actions > Place photos > Run workflow ก่อนใส่ งานจะข้ามเฉยๆ (live มี 275 รูปปกรอย้ายไป R2)
