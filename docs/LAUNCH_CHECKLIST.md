# สิ่งที่ต้องทำก่อนเปิดใช้งานจริง

อัปเดตล่าสุด 2026-10-11 โดย Claude Code

เอกสารนี้รวมงานที่ตั้งใจเลื่อนไว้ระหว่างทำต้นแบบ เมื่อเลื่อนงานใดเพิ่ม ให้มาเติมที่นี่ เมื่อทำเสร็จให้ติ๊กออก
รายละเอียดเชิงเทคนิคของแต่ละระบบอยู่ใน [API.md](API.md) และ [HANDOFF.md](HANDOFF.md)

ลำดับความสำคัญ: **ต้องทำ** = เปิดไม่ได้ถ้ายังไม่เสร็จ · **ควรทำ** = เปิดได้แต่มีความเสี่ยง · **ทำทีหลังได้** = ปรับปรุงหลังเปิด

---

## 1. ระบบพื้นฐานและข้อมูล (ต้องทำ)

- [ ] **ย้ายข้อมูลไปฐานข้อมูลจริง** ตอนนี้เก็บเป็นไฟล์ JSON ในเครื่อง ซึ่งบน Vercel ข้อมูลจะหายเมื่อระบบรีสตาร์ต และรองรับได้ราวหลักสิบถึงหลักร้อยคน
  - ไฟล์ที่ต้องย้าย: `data/members.json`, `data/moments.json`, `data/stories.json`, `data/notifications.json`, `data/chill_database.json` (กิจกรรม), `data/discovery_content.json`, ข้อมูลหลัก (master data) และบันทึกการทำงานของแอดมิน (audit log)
  - โค้ดแยกชั้นเก็บข้อมูลไว้แล้ว (`memberRepository`, `momentRepository`, `lib/social/jsonStore.ts`) จึงสลับได้โดยไม่ต้องแก้หน้าจอ
  - ต้องเลือกผู้ให้บริการฐานข้อมูลก่อน (แนะนำ Postgres)
- [ ] **ย้ายรูปไปที่เก็บไฟล์ถาวร** ระบบอัปโหลดรองรับ Vercel Blob แล้ว แต่ยังไม่ได้ทดสอบบนระบบจริง ต้องตั้งค่า token และทดสอบอัปโหลด แสดงผล และลบ
  - ถ้ารูปอยู่บน Blob ต้องเพิ่มโดเมนใน `next.config` (`images.remotePatterns`) เพื่อให้ระบบย่อรูปหลายขนาดทำงานกับรูปเหล่านั้น ตอนนี้ย่อเฉพาะรูปใน `/uploads/`
- [ ] **ตั้งค่าตัวแปรบน Vercel:** `AUTH_SECRET`, `ADMIN_PASSWORD` และค่าของ OAuth ทุกผู้ให้บริการที่จะเปิดใช้
- [ ] **ตั้งค่าระบบส่งอีเมล:** `RESEND_API_KEY` และ `MAIL_FROM` พร้อมยืนยันโดเมนผู้ส่ง
  - สำคัญมาก: ถ้าไม่มีระบบส่งอีเมล สมาชิกจะยืนยันอีเมลไม่ได้ และจะโพสต์หรือคอมเมนต์ไม่ได้เลย (ตอนพัฒนาใช้ลิงก์ที่แสดงบนหน้าจอแทน ซึ่งระบบจริงไม่แสดง)
  - ใช้กับอีเมล 2 แบบ: ยืนยันอีเมล และรีเซ็ตรหัสผ่าน
- [ ] **เปลี่ยนหรือจำกัดสิทธิ์ Google Places key** เพราะ key เคยถูกวางในแชต

## 2. ข้อมูลตัวอย่างที่ต้องลบ (ต้องทำ)

รายการเต็มอยู่ใน [DESIGN_SYSTEM.md](../DESIGN_SYSTEM.md) หัวข้อ 12 รายการหลักคือ

- [ ] **บัญชีตัวอย่าง 24 บัญชี** (อีเมลลงท้าย `@sample.invalid`): ลบไฟล์ `data/sampleMembers.ts`, `lib/members/sampleMembers.ts`, เอาการเรียก `ensureSampleMembers()` ออกจาก 3 เส้นทาง API แล้วลบบัญชีกับโพสต์ของบัญชีเหล่านั้น
- [ ] **โพสต์ตัวอย่างในหน้า Moments** (สร้างจาก `MOCK_POSTS` ตอนเริ่มระบบครั้งแรก): เอาการสร้างอัตโนมัติออกจาก `lib/moments/jsonMomentRepository.ts`
- [ ] **กิจกรรม โฮสต์ และโปรไฟล์ตัวอย่าง:** `data/mockData.ts`, `data/profilesData.ts` และส่วนที่หน้า My Hub กับหน้ากิจกรรมยังอ่านจากข้อมูลเหล่านี้
- [ ] **กิจกรรมแนะนำด้านขวาของหน้า Moments** ยังอ่านจาก `MOCK_EVENTS` ให้เปลี่ยนเป็น `/api/events`
- [ ] ตรวจว่าไม่มีชื่อ รูป ตัวเลข หรือรีวิวที่แต่งขึ้นเหลือในหน้าใด

## 3. ความปลอดภัยและกฎหมาย (ต้องทำ)

- [ ] **ตรวจว่าหน้า admin และ API ของ admin ต้อง login บนระบบจริง** ระหว่างทดสอบในโหมดพัฒนา เบราว์เซอร์ทดสอบเรียก API ของ admin และลบบัญชีได้โดยไม่ได้ login ต้องยืนยันว่าเป็นพฤติกรรมเฉพาะโหมดพัฒนา และระบบจริงปฏิเสธ
- [ ] **ให้นักกฎหมายตรวจข้อตกลงการใช้งานและนโยบายความเป็นส่วนตัว** แล้วเปลี่ยนเลขเวอร์ชันจาก `2026-10-draft` (`lib/members/preferences.ts`) เป็นฉบับจริง รวมถึงข้อความคำมั่นของคอมมูนิตี้
- [ ] **ใส่ลิงก์ไปหน้า `/legal` ในส่วนท้ายของเว็บ** (ไฟล์ของ Gemini)
- [ ] **เอาการเลือกบทบาทจำลองออก** (`lib/useAuth.ts` ยังเก็บบทบาทไว้ในเบราว์เซอร์เพื่อดูตัวอย่างหน้าจอ) บทบาทจริงต้องมาจากเซิร์ฟเวอร์เท่านั้น
- [ ] **ตรวจการตั้งค่าให้เครื่องมือค้นหาเก็บข้อมูล** หน้าเว็บมีทั้ง `noindex` และ `index, follow` อยู่พร้อมกัน ต้องเลือกให้ชัด
- [ ] ตรวจเพดานการใช้งานบนระบบจริง: สมัครสมาชิก 10 ครั้งต่อชั่วโมง และ login 10 ครั้งต่อ 15 นาที ต่อ IP (ตอนพัฒนาผ่อนการสมัครเป็น 300 ครั้ง)
- [ ] กำหนดคนรับผิดชอบคิวตรวจของ admin (สมาชิกน่าสงสัย คำขอเป็นโฮสต์ โมเมนต์ที่ถูกรายงาน กิจกรรมที่รออนุมัติ) และเวลาตอบกลับ

## 4. ฟีเจอร์ที่ยังไม่ครบ (ควรทำ)

- [x] การเข้าร่วมกิจกรรมผูกกับบัญชีสมาชิกแล้ว (2026-10-11) มายฮับอ่านจากบัญชี
- [ ] **หน้างานแฟร์ (`app/fairs/[id]`) ยังเก็บกลุ่มย่อยและการเข้าร่วมกลุ่มย่อยในเบราว์เซอร์** รวมถึงเครื่องหมาย "ไม่ได้ไป" และ "รีวิวแล้ว" ในมายฮับ
- [ ] **มายฮับ: บัตรเข้างาน แชตกลุ่ม รีวิวโฮสต์ ทิป แต้ม ระดับ และของรางวัล ยังเป็นของจำลอง** (บัตรและรีวิวจะทำจริง ทิปจะซ่อน แต้มกับของรางวัลทำพร้อมหน้าชาเลนจ์ แชตรอตัดสินใจ)
- [ ] **จำนวนที่นั่งในหน้ารายการอาจช้ากว่าจริงได้ถึง 30 วินาที** เพราะรายการกิจกรรมถูกแคชไว้ การเข้าร่วมจริงตรวจที่นั่งล่าสุดเสมอ จึงไม่เกิดการจองเกิน
- [ ] **ยืนยันเบอร์โทรด้วย OTP** เลื่อนไว้ตามที่ตกลง ช่วยกันบัญชีปลอมได้มากกว่าอีเมล
- [ ] **การบล็อกมีผลเฉพาะโมเมนต์ สตอรี่ และการแจ้งเตือน** ยังไม่ซ่อนคอมเมนต์ กิจกรรม หรือการค้นหา
- [ ] **ธงเตือนใช้รายการคำ** จึงตั้งธงผิดได้ ต้องทบทวนรายการคำหลังเห็นข้อมูลจริง
- [ ] **หน้า admin ยังไม่มีตัวกรองแยกบัญชีตัวอย่าง** (ไม่จำเป็นถ้าลบบัญชีตัวอย่างตามข้อ 2)
- [ ] **งานของ Gemini ที่ค้างใน HANDOFF:** BE-013 ถึง BE-025

## 5. รองรับผู้ใช้จำนวนมาก (ควรทำ ก่อนโปรโมต)

ทำหลังย้ายฐานข้อมูลในข้อ 1

- [ ] ฟีดและการค้นหาใช้ดัชนีของฐานข้อมูล แทนการดึงทุกรายการมากรอง
- [ ] เก็บตัวเลขนับสำเร็จรูป (หัวใจ คอมเมนต์ ผู้ติดตาม) แทนการนับใหม่ทุกครั้ง
- [ ] แบ่งหน้าแบบต่อจากรายการล่าสุด แทนเลขหน้า เพื่อไม่ให้โพสต์ซ้ำหรือข้ามเมื่อมีโพสต์ใหม่เข้ามา
- [ ] ย้ายเพดานการใช้งานไปที่เก็บกลาง (ตอนนี้จำในหน่วยความจำของเครื่องเดียว)
- [ ] งานเบื้องหลัง: ลบสตอรี่ที่หมดอายุและไฟล์รูปที่ไม่มีโพสต์อ้างถึง
- [ ] เปิด CDN สำหรับรูป
- [ ] ทดสอบรับโหลดก่อนเปิด

## 6. การทดสอบที่ยังไม่ได้ทำ (ควรทำ)

- [ ] เบราว์เซอร์อื่นนอกจาก Chrome (Safari บน iPhone สำคัญที่สุด) และเครื่องจริง
- [ ] เน็ตช้าและการอัปโหลดรูปขนาดใหญ่จากมือถือ
- [ ] โปรแกรมอ่านหน้าจอ
- [ ] login ด้วย Google, Facebook และ LINE บนโดเมนจริง
- [ ] ลบบัญชีแล้วข้อมูลหายครบ (โพสต์ คอมเมนต์ สตอรี่ การแจ้งเตือน) บนฐานข้อมูลจริง
- [ ] แก้ lint error ที่ค้างในหน้าของ Gemini

## 7. ทำทีหลังได้

- [ ] การแจ้งเตือนแบบทันที และการแจ้งเตือนบนมือถือ (ตอนนี้โหลดซ้ำทุก 1 นาที)
- [ ] บันทึกสัดส่วนรูปของโพสต์เก่า เพื่อไม่ให้การจัดวางเปลี่ยนตอนรูปโหลด
- [ ] แก้ไขรูปของโพสต์หลังโพสต์แล้ว (ตอนนี้แก้ได้เฉพาะข้อความ)
- [ ] ตอบกลับคอมเมนต์ และการกล่าวถึงสมาชิก
