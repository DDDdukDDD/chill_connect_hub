# สิ่งที่ต้องทำก่อนเปิดใช้งานจริง

อัปเดตล่าสุด 2026-10-11 โดย Claude Code

เอกสารนี้รวมงานที่ตั้งใจเลื่อนไว้ระหว่างทำต้นแบบ เมื่อเลื่อนงานใดเพิ่ม ให้มาเติมที่นี่ เมื่อทำเสร็จให้ติ๊กออก
รายละเอียดเชิงเทคนิคของแต่ละระบบอยู่ใน [API.md](API.md) และ [HANDOFF.md](HANDOFF.md)

ลำดับความสำคัญ: **ต้องทำ** = เปิดไม่ได้ถ้ายังไม่เสร็จ · **ควรทำ** = เปิดได้แต่มีความเสี่ยง · **ทำทีหลังได้** = ปรับปรุงหลังเปิด

---

## 1. ระบบพื้นฐานและข้อมูล (ต้องทำ)

- [ ] **ย้ายข้อมูลไปฐานข้อมูลจริง** ตอนนี้เก็บเป็นไฟล์ JSON ในเครื่อง ซึ่งบน Vercel ข้อมูลจะหายเมื่อระบบรีสตาร์ต และรองรับได้ราวหลักสิบถึงหลักร้อยคน
  - ไฟล์ที่ต้องย้าย: `data/members.json`, `data/moments.json`, `data/stories.json`, `data/notifications.json`, `data/chill_database.json` (กิจกรรม), `data/discovery_content.json`, ข้อมูลหลัก (master data) และบันทึกการทำงานของแอดมิน (audit log)
  - โค้ดแยกชั้นเก็บข้อมูลไว้แล้ว (`memberRepository`, `momentRepository`, `lib/social/jsonStore.ts`) จึงสลับได้โดยไม่ต้องแก้หน้าจอ
  - ต้องเลือกผู้ให้บริการฐานข้อมูลก่อน (แนะนำ Postgres)
- [ ] **ย้ายรูปไปที่เก็บไฟล์ถาวร** ระบบอัปโหลดรองรับ Vercel Blob แล้ว แต่ยังไม่ได้ทดสอบบนระบบจริง ต้องตั้งค่า token และทดสอบอัปโหลด แสดงผล และลบ
  - ถ้ารูปอยู่บน Blob ต้องเพิ่มโดเมนใน `next.config` (`images.remotePatterns`) เพื่อให้ระบบย่อรูปหลายขนาดทำงานกับรูปเหล่านั้น ตอนนี้ย่อเฉพาะรูปใน `/uploads/`
- [ ] **ตั้งค่าตัวแปรบน Vercel:** `AUTH_SECRET`, `ADMIN_PASSWORD` และค่าของ OAuth ทุกผู้ให้บริการที่จะเปิดใช้
- [ ] **ตั้งค่าระบบส่งอีเมล:** `RESEND_API_KEY` และ `MAIL_FROM` พร้อมยืนยันโดเมนผู้ส่ง
  - สำคัญมาก: ถ้าไม่มีระบบส่งอีเมล สมาชิกจะยืนยันอีเมลไม่ได้ และจะโพสต์หรือคอมเมนต์ไม่ได้เลย (ตอนพัฒนาใช้ลิงก์ที่แสดงบนหน้าจอแทน ซึ่งระบบจริงไม่แสดง)
  - ใช้กับอีเมล 2 แบบ: ยืนยันอีเมล และรีเซ็ตรหัสผ่าน
- [ ] **เปลี่ยนหรือจำกัดสิทธิ์ Google Places key** เพราะ key เคยถูกวางในแชต

## 2. ข้อมูลตัวอย่างที่ต้องลบ (ต้องทำ)

รายการเต็มอยู่ใน [DESIGN_SYSTEM.md](../DESIGN_SYSTEM.md) หัวข้อ 12 รายการหลักคือ

- [ ] **บัญชีตัวอย่าง 24 บัญชี** (อีเมลลงท้าย `@sample.invalid`): ลบไฟล์ `data/sampleMembers.ts`, `lib/members/sampleMembers.ts`, เอาการเรียก `ensureSampleMembers()` ออกจาก 3 เส้นทาง API แล้วลบบัญชีกับโพสต์ของบัญชีเหล่านั้น
- [ ] **โพสต์ตัวอย่างในหน้า Moments** (สร้างจาก `MOCK_POSTS` ตอนเริ่มระบบครั้งแรก): เอาการสร้างอัตโนมัติออกจาก `lib/moments/jsonMomentRepository.ts`
- [ ] **กิจกรรม โฮสต์ และโปรไฟล์ตัวอย่าง:** `data/mockData.ts`, `data/profilesData.ts` และส่วนที่หน้า My Hub กับหน้ากิจกรรมยังอ่านจากข้อมูลเหล่านี้
- [ ] **ชาเลนจ์ตัวอย่าง 15 รายการ** (`MOCK_CHALLENGES` ใน `data/mockData.ts` รวม 7 รายการที่ย้ายมาจากแถวหน้าแรก): ลบออกจากคลังผ่านหน้า admin แล้วเอาการเติมอัตโนมัติ (`addNewSeedQuests`) ออกจาก `lib/db/adapters/jsonAdapter.ts`; จำนวนผู้ร่วมที่เขียนไว้ในชาเลนจ์ตัวอย่าง (`participantsCount`) เป็นเลขสมมติ ต้องเป็น 0 ก่อนเปิดจริง
- [ ] **ชาเลนจ์ตัวอย่างที่ยังไม่เริ่ม 5 รายการ** (สร้างผ่านหน้าแอดมินเมื่อ 2026-10-15 เพื่อทดสอบฟอร์มและกลุ่ม "กำลังจะมาถึง"): ทะเลหมอกต้นหนาว, ตลาดนัดสุดสัปดาห์, ส่งท้ายปีที่งานแฟร์, ไหว้พระรับปีใหม่ 5 วัด, เพื่อนใหม่ต้นปี อยู่ในฐานข้อมูล ไม่ได้อยู่ในโค้ด ลบได้จากหน้าแอดมิน "ชาเลนจ์ & ภารกิจ" (หรือเก็บไว้ใช้จริง ถ้าเจ้าของเห็นว่าเหมาะ)
- [ ] **รหัสรางวัลของแบรนด์** (`data/quest_vouchers.json`): ทีมงานตรวจและทำเครื่องหมายว่าใช้แล้วได้ในหน้า admin ชาเลนจ์ (2026-10-13) แต่แบรนด์ยังตรวจเองไม่ได้ ต้องตกลงวิธีกับแบรนด์ก่อนมีแบรนด์จริง
- [x] แถวชาเลนจ์และแถวโมเมนต์ในหน้าแรกอ่านจาก `/api/quests` และ `/api/moments` แล้ว (2026-10-13)
- [x] กิจกรรมและชาเลนจ์แนะนำในหน้า Moments อ่านจาก `/api/events` และ `/api/quests` แล้ว (2026-10-11)
- [ ] **ตัวช่วยเติมข้อมูลตัวอย่าง:** ลบ `app/api/dev/demo/route.ts` และแถบ "โหมดพัฒนา" ในมายฮับ (ตอนนี้ปิดตัวเองบนระบบจริง แต่ควรลบออก)
- [ ] ตรวจว่าไม่มีชื่อ รูป ตัวเลข หรือรีวิวที่แต่งขึ้นเหลือในหน้าใด

## 3. ความปลอดภัยและกฎหมาย (ต้องทำ)

- [ ] **ตรวจว่าหน้า admin และ API ของ admin ต้อง login บนระบบจริง** ระหว่างทดสอบในโหมดพัฒนา เบราว์เซอร์ทดสอบเรียก API ของ admin และลบบัญชีได้โดยไม่ได้ login ต้องยืนยันว่าเป็นพฤติกรรมเฉพาะโหมดพัฒนา และระบบจริงปฏิเสธ
- [ ] **ให้นักกฎหมายตรวจข้อตกลงการใช้งานและนโยบายความเป็นส่วนตัว** แล้วเปลี่ยนเลขเวอร์ชันจาก `2026-10-draft` (`lib/members/preferences.ts`) เป็นฉบับจริง รวมถึงข้อความคำมั่นของคอมมูนิตี้
- [ ] **ใส่ลิงก์ไปหน้า `/legal` ในส่วนท้ายของเว็บ** (ไฟล์ของ Gemini)
- [ ] **เอาการเลือกบทบาทจำลองออก** (`lib/useAuth.ts` ยังเก็บบทบาทไว้ในเบราว์เซอร์เพื่อดูตัวอย่างหน้าจอ) บทบาทจริงต้องมาจากเซิร์ฟเวอร์เท่านั้น
- [ ] **ตรวจการตั้งค่าให้เครื่องมือค้นหาเก็บข้อมูล** หน้าเว็บมีทั้ง `noindex` และ `index, follow` อยู่พร้อมกัน ต้องเลือกให้ชัด
- [ ] ตรวจเพดานการใช้งานบนระบบจริง: สมัครสมาชิก 10 ครั้งต่อชั่วโมง และ login 10 ครั้งต่อ 15 นาที ต่อ IP (ตอนพัฒนาผ่อนการสมัครเป็น 300 ครั้ง)
- [ ] **ทริปชวนเพื่อน (Spot Buddy): ทำ OTP เบอร์โทรก่อนเปิดให้คนจริงใช้** ตอนนี้ยืนยันด้วยอีเมลเท่านั้น และอีเมลปลอมสร้างได้ไม่จำกัด
- [ ] **ทริปชวนเพื่อน: ให้นักกฎหมายเพิ่มในข้อตกลงว่าแพลตฟอร์มเป็นตัวกลาง ไม่ใช่ผู้จัดทริป**
- [ ] **ทริปชวนเพื่อน: ทริปที่คนไม่ครบ 3 คนยังไม่ถูกยกเลิกอัตโนมัติ** ระบบแค่แสดงว่ายังไม่ยืนยัน ต้องเพิ่มการยกเลิกก่อนเวลานัดและการแจ้งเตือนผู้เข้าร่วม
- [ ] **ทริปชวนเพื่อน: เงื่อนไข "เคยไปกิจกรรมมาก่อน" นับงานแฟร์ที่เพิ่มไว้ในแผนแล้วงานจบ** ซึ่งไม่มีการยืนยันว่าไปจริง ต้องทบทวนเมื่อมีผู้ใช้จริง
- [ ] **ทริปชวนเพื่อน: ทีมงานต้องไล่ติดป้าย "นัดเจอได้" ให้สถานที่** ทุกแห่งเริ่มต้นเป็นปิด (หน้า admin > สถานที่ > แก้ไข) ยังไม่มีการติดป้ายทีละหลายแห่ง
- [ ] **ทริปชวนเพื่อน: ยังไม่มีปุ่มส่งรายละเอียดทริปให้คนใกล้ตัวโดยเฉพาะ** ตอนนี้ใช้ปุ่มแชร์กิจกรรมที่มีอยู่
- [ ] กำหนดคนรับผิดชอบคิวตรวจของ admin (สมาชิกน่าสงสัย คำขอเป็นโฮสต์ โมเมนต์ที่ถูกรายงาน รายงานความปลอดภัยของกิจกรรมและสถานที่ กิจกรรม สถานที่ และชาเลนจ์ที่รออนุมัติ) และเวลาตอบกลับ

## 4. ฟีเจอร์ที่ยังไม่ครบ (ควรทำ)

- [x] การเข้าร่วมกิจกรรมผูกกับบัญชีสมาชิกแล้ว (2026-10-11) มายฮับอ่านจากบัญชี
- [x] กลุ่มนัดหมายในงานแฟร์และแชตกลุ่มเก็บที่เซิร์ฟเวอร์แล้ว (2026-10-11)
- [x] แชตกลุ่ม: สมาชิกรายงานข้อความได้ และทีมงานลบข้อความที่ถูกรายงานได้จากหน้า admin (2026-10-11)
- [x] ทีมงานเปิดอ่านแชตทั้งห้องได้จากรายงานของห้องนั้น และลบข้อความอื่นในห้องได้ (2026-10-11) การเปิดอ่านถูกบันทึกในประวัติการทำงาน
- [ ] **แชตกลุ่มอัปเดตด้วยการถามซ้ำทุก 4 วินาที** ไม่ใช่แบบทันที
- [ ] **ห้องแชตที่ไม่มีใครรายงาน ทีมงานเปิดอ่านไม่ได้** (ตั้งใจไว้เพื่อความเป็นส่วนตัว) ต้องตัดสินใจก่อนเปิดจริงว่าพอหรือไม่ และระบุในนโยบายความเป็นส่วนตัวว่าทีมงานอ่านแชตได้เมื่อมีรายงาน
- [ ] **กลุ่มนัดหมายในงานแฟร์เปิดได้ทันทีโดยไม่ผ่านทีมงาน** (ต่างจากกิจกรรมคอมมูนิตี้) ต้องตัดสินใจว่าพอหรือไม่ก่อนเปิดจริง
- [x] มายฮับ: บัตรเข้างานพร้อมรหัส เช็กอินโดยคนจัด และรีวิวหลังกิจกรรม เป็นของจริงแล้ว (2026-10-11) ส่วนทิปเอาออก
- [ ] **มายฮับ: แต้ม ระดับ ของรางวัล และการยืนยันชาเลนจ์ ยังเป็นของจำลอง** (ทำพร้อมหน้าชาเลนจ์)
- [x] รีวิว: สมาชิกรายงานรีวิวได้ และทีมงานลบรีวิวที่ถูกรายงานได้จากหน้า admin (2026-10-11)
- [ ] **กิจกรรมทางการและกิจกรรมตัวอย่างไม่มีคนจัดที่เป็นสมาชิก** จึงไม่มีการเช็กอิน และยังใช้การกด "ไปแล้ว/ไม่ได้ไป" เองในเบราว์เซอร์
- [ ] **จำนวนที่นั่งในหน้ารายการอาจช้ากว่าจริงได้ถึง 30 วินาที** เพราะรายการกิจกรรมถูกแคชไว้ การเข้าร่วมจริงตรวจที่นั่งล่าสุดเสมอ จึงไม่เกิดการจองเกิน
- [ ] **ยืนยันเบอร์โทรด้วย OTP** เลื่อนไว้ตามที่ตกลง ช่วยกันบัญชีปลอมได้มากกว่าอีเมล
- [x] การบล็อกซ่อนคอมเมนต์ในโมเมนต์ และกิจกรรมที่คนถูกบล็อกสร้าง ทั้งในรายการและการค้นหา (2026-10-11)
- [ ] **การบล็อกยังไม่ซ่อนรีวิวที่คนถูกบล็อกเขียน และหน้าโปรไฟล์ของกันและกันยังเปิดดูได้**
- [ ] **ตรวจบนระบบจริงว่ารายการกิจกรรมของคนที่บล็อกผู้อื่นไม่ถูกแคชร่วมกับคนอื่น** (`GET /api/events` ส่ง `Vary: Cookie` และ `no-store` เฉพาะกรณีนี้ ต้องยืนยันกับ CDN ของ Vercel)
- [ ] **ธงเตือนใช้รายการคำ** จึงตั้งธงผิดได้ ต้องทบทวนรายการคำหลังเห็นข้อมูลจริง
- [ ] **หน้า admin ยังไม่มีตัวกรองแยกบัญชีตัวอย่าง** (ไม่จำเป็นถ้าลบบัญชีตัวอย่างตามข้อ 2)
- [ ] **เนื้อหาแต่งเติมของข้อมูลตัวอย่าง:** หน้ารายละเอียดยังเติมรูปสต็อก สถิติโฮสต์ และข้อความตายตัวให้ข้อมูลตัวอย่าง (ที่มา `sample` ใน `lib/contentOrigin.ts`) เมื่อลบข้อมูลตัวอย่างตามข้อ 2 แล้ว ให้ลบโค้ดส่วนที่อยู่หลังเงื่อนไข `sample` ในหน้า `/community/[id]`, `/fairs/[id]`, `/spots/[id]` และตัวเลือกรูปใน `lib/eventImageResolver.ts`, `lib/spotImageResolver.ts`
- [ ] **ค้นหาสถานที่ตอนปักหมุดใช้ OpenStreetMap (Nominatim) แบบสาธารณะ** จำกัดราว 1 ครั้งต่อวินาที และหาร้านเล็กๆ ไม่ค่อยเจอ ก่อนเปิดจริงให้เลือก: ใช้ Google Places (ต้องเปิด key และมีค่าใช้จ่าย) หรือผู้ให้บริการค้นหาแบบเสียเงิน
- [ ] **งานของ Gemini ที่ค้างใน HANDOFF:** BE-013 ถึง BE-025
- [ ] **การตรวจรูปที่ใช้นับชาเลนจ์ยังเป็นงานมือ:** แอดมินกด "ไม่นับเป็นการไป" ได้ที่หน้าโมเมนต์ (ตัวกรอง "ใช้นับชาเลนจ์") แต่ระบบยังไม่ตรวจตำแหน่งหรือเวลาถ่ายของรูป และรหัสรางวัลที่ออกไปแล้วไม่ถูกเรียกคืนเมื่อรูปถูกไม่นับภายหลัง ก่อนมีแบรนด์จริงควรให้รางวัลจากแบรนด์ออกหลังแอดมินตรวจรูปแล้ว
