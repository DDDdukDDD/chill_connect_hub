# iPhone app (Capacitor)

The iPhone app is a native shell (Capacitor 8) that opens **www.chillwaa.com**. The pages inside are the website, so every deploy reaches the app at once. A new App Store version is needed only when the shell changes (icon, permissions, native plugins, version number).

Owner decision 2026-11-17: the owner's circle all use iPhone, so the iPhone app comes before Android (docs/ANDROID_APP.md). No one on the team has a Mac: the app is built on GitHub Actions macOS runners and tested through TestFlight.

## What is in the repo

| Path | What it does |
| :--- | :--- |
| `ios-app/package.json` | Capacitor and its plugins, apart from the website's packages (Vercel never installs them: `.vercelignore`) |
| `ios-app/capacitor.config.json` | App id `com.chillwaa.app` (same as Android, permanent), name, `server.url` = the live site |
| `ios-app/www/index.html` | Shown only when the site cannot load (no internet) |
| `ios-app/ios/` | The Xcode project (Swift Package Manager, no CocoaPods), generated by `cap add ios`. `Info.plist` holds the Thai texts iOS shows when the site asks for the camera, microphone, photos or location; without them the app crashes |
| `.github/workflows/ios-build.yml` | Unsigned simulator build on every change to `ios-app/`, or by hand (Actions → iOS build → Run workflow) |

Capacitor 8's CLI needs Node 22; this computer has Node 20, so run it as `npx -y -p node@22.12.0 -- node node_modules/@capacitor/cli/bin/capacitor sync ios` inside `ios-app/`.

4. **Register the App ID:** developer.apple.com → Account → Certificates, Identifiers & Profiles → Identifiers → **+** → App IDs → App → Description `Chillwaa`, Bundle ID **Explicit** `com.chillwaa.app`. Tick **Associated Domains**, **Push Notifications** and **Sign In with Apple** (needed in steps 2–4 below; ticking them now saves a second visit) → Continue → Register.
5. **Create the app in App Store Connect:** appstoreconnect.apple.com → Apps → **+** → New App → iOS, name `Chillwaa` (if taken: `Chillwaa: ชวนเพื่อนไปเที่ยว` or similar, the name can change later), primary language Thai, bundle ID `com.chillwaa.app`, SKU `chillwaa-ios`, full access. TestFlight uploads fail until this exists.
6. **Run the first build:** github.com → the repository → Actions → **iOS build** → Run workflow → branch `claude` → Run. About 15 minutes; the build then shows in App Store Connect → the app → TestFlight after Apple processes it (another 5–30 minutes).
7. **APNs key for native push (BE-428):** developer.apple.com → Certificates, Identifiers & Profiles → **Keys** → **+** → name `Chillwaa Push` → tick **Apple Push Notifications service (APNs)** → Continue → Register → **Download** the .p8 (only once) and note the **Key ID**. On Vercel → Project → Settings → Environment Variables, Production: `APNS_KEY_ID` = the Key ID, `APNS_PRIVATE_KEY` = the whole .p8 text (`APPLE_TEAM_ID` is already there). Redeploy. Then merge `claude` → `main` so the iOS workflow uploads a build with push, update it in TestFlight, turn on แจ้งเตือนบนเครื่องนี้ in settings, and have a friend follow you or comment.

## Still to build (in this order)

1. **Signed build to TestFlight** (BE-407, built, first run waits on owner steps 4–6): job `testflight` in `ios-build.yml`. The archive is built unsigned, then `xcodebuild -exportArchive -allowProvisioningUpdates` with the API key lets Apple sign it with a cloud-managed distribution certificate and uploads it; nothing to keep in secrets except the key. Build number = the workflow run number. Runs by hand, or on a push to `main` that changes `ios-app/`. If Apple refuses cloud signing for an App Manager key ("Cloud signing permission error"), make a new key with the **Admin** role and replace the two key secrets. Push entitlement `aps-environment` comes with step 4.
2. **Social sign-in inside the app.** Built as BE-411 (2026-11-18) with a custom scheme instead of a Universal Link: `WebAuthPlugin.swift` opens `ASWebAuthenticationSession`, which catches the redirect to `chillwaa://auth?...` itself, so no Associated Domains file is needed for sign-in. The page trades the code for its session (`POST /api/auth/member/app-session`, bound to a verifier the page keeps). Registered in `MainViewController.swift`, which `SceneDelegate.swift` makes as the window's root (the scene builds its own window, so Main.storyboard is not used). Original plan: Google refuses sign-in inside an embedded web view (`disallowed_useragent`), and Facebook and LINE are unreliable there. The app must open sign-in in the system sheet (`ASWebAuthenticationSession`, via `@capacitor/browser` or a small plugin) and come back through a Universal Link (`/.well-known/apple-app-site-association`, entitlement `applinks:www.chillwaa.com`) that hands the session to the web view.
3. **Sign in with Apple** (App Review 4.8, required because Google, Facebook and LINE are offered): a new provider beside the others in `app/api/auth/member/oauth/[provider]`, needs a Services ID and a key from the developer account.
4. **Native push** (App Review 4.2): built as BE-428. The page asks iOS through Capacitor PushNotifications (`lib/appClient.ts`: the same switch in settings), `AppDelegate.swift` hands the token over, `POST /api/push { apns }` keeps it in `app.push_subscriptions` as `apns:<token>` (no migration), and `sendPush` (`lib/social/push.ts`) sends those through APNs over HTTP/2 (`lib/social/apns.ts`). A tapped notice opens its `url`. `App.entitlements` (aps-environment production) is set on the target, and the workflow signs the unsigned archive ad hoc with it so Apple's re-signing keeps push. Needs owner step 7 below.
5. **Share** through the native sheet: built as BE-428. Inside the app `navigator.share` is pointed at Capacitor Share once at start (`installNativeShareSheet`), so every share button opens the iOS sheet; a closed sheet is an AbortError as before.
6. **Account deletion**: profile menu → ตั้งค่าบัญชี → **ลบบัญชี** (its own link since BE-428) → the "ข้อมูลของฉัน" part → delete and confirm. Since BE-427 it also revokes the Sign in with Apple token.
7. **Store listing**: screenshots (6.7" and 6.1"), Thai description, privacy policy URL (`/privacy`), privacy "nutrition label", age rating, a demo account for App Review.
