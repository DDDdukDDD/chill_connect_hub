# การเก็บร่องรอยการกระทำ (Traceability)

เป้าหมาย (เจ้าของ 2026-11-13): เก็บ log การกระทำให้พอ เพื่อใช้ต่อยอดเรื่องโมเดลรายได้ และเรื่องแบ่งส่วนแบ่งให้ creator ("แต้มพาไป" ใน [LAUNCH_CHECKLIST.md](LAUNCH_CHECKLIST.md)) ก่อนเปิดตัวยังไม่จ่ายเงินใคร และไม่สัญญาเรื่องเงินกับผู้ใช้ แต่ต้องเก็บข้อมูลไว้ตั้งแต่วันนี้ เพราะข้อมูลที่ไม่ได้เก็บไว้ ย้อนกลับไปเก็บไม่ได้

คำถามที่ข้อมูลต้องตอบได้:
1. **ใครพาใครไป:** คนนี้เข้าตี้ บันทึกที่ หรือไปถึงที่ เพราะโพสต์ของใคร หรือเพราะใครชวน
2. **creator คนนี้มีคนเห็นกี่คน:** ยอดคนเห็นโพสต์ต่อวัน เก็บแบบไม่หายไปตามเวลา
3. **ร้านหรือแบรนด์ได้อะไร:** มีคนมาจริงกี่คน กดออกไปจองหรือซื้อตั๋วกี่ครั้ง และใช้คูปองที่ร้านกี่ครั้ง
4. **platform มีรายได้จากตรงไหน:** การ์ดสนับสนุนมีคนเห็นกี่ครั้ง และมีคนกดกี่ครั้ง

## 2. วิธีเก็บ

### 2.1 สมุดบันทึกการกระทำ (`app.action_log`, migration 0052)
เป็นตารางเดียวที่บันทึกการกระทำที่มีค่า บันทึกเพิ่มอย่างเดียว ไม่แก้และไม่ลบ แต่ละแถวมีข้อมูลดังนี้:
- **ใคร** (`member_id`) **ทำอะไร** (`action`) **กับอะไร** (`target_type`, `target_ref`)
- **มาจากไหน** (`source_type`: `moment` | `profile` | `invite` | `share`, `source_ref`)
- **เครดิตให้ใคร** (`credited_id`): เจ้าของโพสต์ คนที่ชวน หรือเจ้าของโปรไฟล์ ไม่ให้เครดิตตัวเอง
- `meta` (jsonb) สำหรับรายละเอียดเพิ่ม และ `created_at`

การกระทำที่บันทึก: `join` (ตี้/อีเวนต์), `save`, `challenge_join`, `visit`, `invite_yes`, `outbound` (กดออกไปข้างนอก), `sponsored_click`

### 2.2 รู้ได้อย่างไรว่ามาจากไหน
- **จากโพสต์และโปรไฟล์:** เมื่อกดลิงก์จากโพสต์ไปหน้าตี้ ที่เที่ยว หรือชาเลนจ์ เบราว์เซอร์จะจำไว้ในคุกกี้ `cw_via` 7 วัน ว่ามาที่นี่จากโพสต์ไหน (จำได้สูงสุด 8 รายการ) เวลาผู้ใช้เข้าร่วม บันทึก หรือไปถึง server จะอ่านคุกกี้แล้วบันทึกลงสมุด โดยไม่ต้องแก้ทุกจุดที่เรียก API
- **ส่งต่อ:** ถ้าวันนี้บันทึกที่ไว้เพราะโพสต์ของ A แล้วอาทิตย์หน้าไปถึงจริง การไปถึงก็ได้เครดิตให้ A ด้วย (ดูจากแถวก่อนหน้าของคนเดียวกันและที่เดียวกัน ภายใน 60 วัน)
- **ชวนไป:** ตอนตอบ "ไปกัน" รู้อยู่แล้วว่าใครชวน จึงบันทึกเครดิตให้คนชวนตรงๆ
- **เซฟโพสต์ที่มีสถานที่:** บันทึกเครดิตให้เจ้าของโพสต์ตรงๆ

### 2.3 ยอดคนเห็นต่อวัน (`app.moment_daily_views`, ขั้นถัดไป)
ทุกชั่วโมง cron จะรวมยอดจาก `moment_seen` เป็นจำนวนคนเห็นต่อโพสต์ต่อวัน ก่อนที่ข้อมูลอายุเกิน 30 วันจะถูกลบ

### 2.4 กดออกไปข้างนอก และการ์ดสนับสนุน (ขั้นถัดไป)
ใช้ `navigator.sendBeacon` ส่งไปบันทึกเป็น `outbound` หรือ `sponsored_click` คนที่ยังไม่ล็อกอินให้นับเป็นยอดรวม ไม่เก็บว่าเป็นใคร

## 3. ลำดับงาน

| ขั้น | งาน | สถานะ |
| :--- | :--- | :--- |
| 1 | `action_log` + คุกกี้ `cw_via` + บันทึกตอนเข้าร่วม บันทึก เข้าชาเลนจ์ ไปถึง ไปกัน และเซฟโพสต์ | **เสร็จ** BE-372 (2026-11-13) |
| 2 | เจ้าของโพสต์เห็นว่าโพสต์พาคนไปแล้วกี่คน และแอดมินเห็นอันดับ "ใครพาคนไปได้มากที่สุด" | **เสร็จ** BE-372 |
| 3 | ยอดคนเห็นต่อวัน (rollup จาก `moment_seen`) | ยังไม่เริ่ม |
| 4 | นับการกดออกไปข้างนอก และการ์ดสนับสนุน | ยังไม่เริ่ม |
| 5 | ลิงก์แชร์พกชื่อคนแชร์ (`?s=`) เพื่อนับคนที่เปิดและสมัครตาม | ยังไม่เริ่ม |
| 6 | สูตรแต้มพาไป และหน้าครีเอเตอร์ | รอเจ้าของตัดสินใจ และรอคุยกับครีเอเตอร์ |

## 4. ข้อควรระวัง
- **ความเป็นส่วนตัว (PDPA):** ต้องเพิ่มในนโยบายความเป็นส่วนตัวว่าเราบันทึกที่มาของการกระทำ เพื่อวัดผลและให้เครดิตผู้สร้างเนื้อหา คนทั่วไปเห็นได้แค่ยอดรวม ห้ามโชว์ว่าใครพาใครไป
- **ปั่นยอด:** นับคนละครั้งต่อการกระทำต่อเป้าหมาย (`count(distinct member_id)`) ไม่ให้เครดิตตัวเอง และสูตรเงินในอนาคตควรนับเฉพาะ `visit` ที่มีหลักฐาน หรือ `join` ที่โฮสต์ยืนยันว่ามาจริง
- **บัญชีถูกลบ:** แถวของคนที่ลบบัญชีจะหายไปด้วย (cascade) ส่วนเครดิตที่ชี้ไปหาคนนั้นจะกลายเป็นว่าง
